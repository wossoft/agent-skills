# 任务

## 目标与背景

要达成的结果，以及实现所需的最少背景。

## 范围与约定

允许修改的文件或模块、相关接口与契约、明确排除的内容。

## 规则与限制

- 适用的仓库规则和用户约束（worker 不一定会自动加载，重要的写在这里）。
- 与本任务相关的已有改动或上下文（worktree 基于 HEAD，看不到未提交改动）。
- 额外授权（默认不提交、不推送、不发布、不删数据、不改全局配置）。

## 验收标准

主 agent 可以核验的可观察结果。

## 验证

需要执行的检查命令及预期结果；明确不执行或无法执行的检查。

## 修订上下文（仅修订时）

- 在同一 `acpx` 命名会话（`-s <task>`）和 worktree 续聊时：写入上次验收意见与本次聚焦修复的问题清单，但**仍须重申文件范围、禁令与验收标准**（若队列后台进程过期且 adapter 不支持恢复，`acpx` 可能以新底层会话兜底，必要时需补全完整交接上下文）。
- 新建会话、切换 worker 或走 `exec` 重派时：需补全完整上下文与已有改动说明。

---

## Worker 契约（派发时保留）

- 你是被派发的 worker：只完成本任务，禁止再调用 `acpx`、`orchestrate` 或派发给其他 agent。
- 只读任务（诊断/审查/调研）禁止修改、创建或删除任何文件；可写任务只允许修改任务范围内的文件。
- 禁止：`git commit` / `git push`、修改任务范围外的文件；除任务明确要求外不运行单元测试。
- 最后一条回复必须使用以下结构（中文）：
  - `## 改动文件`
  - `## 做了什么`
  - `## 没做什么`
  - `## 不确定 / 风险`
